# branch0 关卡改版：从机关展示到路线解谜

日期：2026-11-02。本文以 branch0 的固定向下重力、准备／释放玩法为准；管理员模式与配重、机关门、升流井、变色等基础机制保留。改动只在当前工作区，未执行 HBuilderX 发行构建。

## 设计依据

- [《纪念碑谷》官方介绍](https://ustwo.com/work/monument-valley/)强调通过观察、探索和改变空间理解路线。本作借鉴“先观察再找到可通行路线”的思路，使用已有高低平台与两段画线，不复刻其视觉或关卡。
- [《双相》官方游戏页](https://www.taptap.cn/app/218343)说明颜色切换是解题规则。本作让球的颜色决定色锁和终点是否响应，使染色成为路线状态，而非终点前的固定手续。
- [《GRIS》App Store 编辑介绍](https://apps.apple.com/us/mac/story/id1486929448)提到颜色与能力随旅程变化。本作只借鉴能力逐步加入、最终组合的节奏，保持原有机关规则。

## 色锁规则与可读性

色锁传感器带 `requiresColor`，只有球带指定颜色进入时才激活对应连接和顺序链。球碰到错误颜色的锁会出现一次提示；重新进入时仍可尝试。染色持续到下一次染色或洗色。终点的 `acceptColor` 独立检查最终颜色；完成机关顺序后误染其他颜色仍不能入仓。关卡画面为染色光、色锁标注颜色与名称，门提示玩家按色序触发。

色锁高度和路线坡度相互制约。第一段解法使用 `[668,520] → [882,540]` 的缓坡；把末端降到第二章原有的 `y=600`，虽能画出合法线路，却会错过高处红锁。这比单纯在终点前加一块洗色区更能体现颜色与空间的关系。

## 数据与验证

`scripts/create-levels-v3.cjs` 是关卡创作源，会生成 `static/game/data/levels.json` 和 `tests/fixtures/solutions.json`；`scripts/build-levels.cjs` 再生成离线脚本 `static/game/js/levels.js`。本轮执行了这两个生成脚本和 93 项 Node 规则测试。测试包含全部 17 关的公开操作通关、主题机关移除反例、旧陡坡错过高处红锁、旧低桥错过高处黄锁、错误颜色不触发色锁、可选洗色区不替代色锁，以及删关后旧存档的解锁兼容等。未运行 HBuilderX、云打包或 Android 真机测试。

公开操作通关证明存在可行解，反例证明所检查的几种旁路无法通关；它们不能替代玩家试玩。下一轮可记录每关首次通关时间、失败位置、是否使用提示和主观难度，再调整建造区容差与提示阶段。
