## 1. 问题与取舍

原0.2的重力输入同时充当了球的水平推进、升空、制动和绕障工具。旧版参考控制器（现已由公开建造操作回放替换）对 17 个运输关逐步改变重力向量；多数关卡先把球送至上方，再跨过场景前往收集器，没有放木板、画线或操作跷跷板。这能证明现有规则下存在解，却不能证明机关承担了解题作用。

因此，问题在于全局操控的能力覆盖了其他机制。仅降低重力灵敏度会增加操作耗时，仍可能让球爬墙、飞越缺口；给收集器额外加“必须碰过跷跷板”条件，又会变成没有空间理由的打卡。

| 方案 | 对机关的影响 | 本次选择 |
| --- | --- | --- |
| 固定向下重力，玩家建造路径、配置配重，再释放模拟 | 高度差、支撑和动量重新成为资源；规则容易预测 | **采用，作为主线统一规则** |
| 小角度全局倾斜 | 仍可持续供给水平能量，改变杠杆平衡；需要逐关重新论证绕行 | 不纳入 0.3 |
| 有次数限制的全局翻转 | 适合独立主题，但需要专门布局和资源提示 | 后续独立章节候选，不作为主线补丁 |

## 2. 统一物理与操作规则

1. 世界重力恒为 `g0=(0,1)`，沿屏幕向下；物理尺度由工程统一设置。玩家不能改变方向、大小或关闭重力。设备倾斜、圆盘、空白滑动、方向键/WASD 均不再输出重力；设置移除重力灵敏度、操控方式和校准入口。普通关与倒映关规则一致。
2. 球不能直接拖动、点击加速或在运行中缩放。平地上的静止球不会无故横向运动：关卡必须提供起始斜坡、落差或明确的机关动力来源。
3. 跷跷板通过配重和力臂改变姿态、托举球或打开通路；高台通过跷跷板、滑轮、弹簧等获得高度；木板提供有限长度的桥面，画线提供缓坡、护栏或导流面。关卡可有多种物理解，不指定唯一画法。
4. 弹簧、水流、局部力场是关卡明确提供的能量来源，须显示方向与范围。其出口动量也纳入绕行检查，不能只检查设施内部。

## 3. 单关循环：准备 → 运行 → 调整

| 阶段 | 玩家可做什么 | 物理与判定 |
| --- | --- | --- |
| 准备 | 放置/旋转木板、画线、撤销/清理、缩放标记物体；在指定区域摆放标记配重或堆叠方块 | 世界不步进；不触发传感器、收集、碎片、顺序链或稳定计时；显示“释放”按钮 |
| 运行 | 观察、暂停、重试或返回准备 | 每步以固定重力推进；全部建造/拖动/缩放入口禁用；不接受运行中撤销支撑来注入动力 |
| 返回准备 | 保留玩家建造方案与合法摆放配置，继续调整 | 球、机关、配重、颜色、Link、顺序链与速度恢复到该次释放前的初态；不保留运行末位置；累计一次重试 |
| 重置本关 | 清空方案，从默认布局重来 | 恢复库存和初始配置；累计一次重试 |

暂停保持原阶段，继续只恢复该阶段；后台切回仍需手动继续。释放是一次明确操作，按钮/空格只切换准备→运行，运行中空格仍用于暂停。计分用时累计准备与运行的前台活跃时间，暂停和后台不计；重试不清空累计时间，结算后重玩才开启新计分。

**建造边界**：木板与画线生成固定碰撞体，不产生推挤冲量；只允许位于关卡可见建造区内，不得与球、地形、机关的实际碰撞轮廓重叠。画线厚度按 12 逻辑像素、单条最多 20 段/1152 像素/5 秒，默认最多 3 条；木板按关卡固定尺寸和库存。非法预览标红，松手不生成、不扣库存。检查采用轮廓相交，不能因外接框相交而拒绝合法曲线。

**配重边界**：仅指定方块可在准备阶段摆放，须位于各自显示的摆放区，并由指定平台或承托件支撑；松手配置速度为零。不能任意举到球上方砸球、把方块搭成跨区桥，或拖动球和整台机关。允许堆叠目标区摆放任务方块，释放后才判定稳定。通过缩放改变密度守恒下的质量；扩张不得挤入其他刚体。撤销只回滚准备配置，不回滚已经发生的通关/永久碎片记录。

## 4. 局部重力的改良：固定升流井

FR-31 保留为第三章 3-2 的固定设施“升流井”，延后介绍。沿用数据类型 `gravityField`，避免引入另一套机制，但对其能力作如下限制：

- 仅影响进入区域的能量球，区内合加速度替换为作者配置的向上向量，`|localGravity|≤2|g0|`；固定位置、范围、方向，玩家无法拖动、缩放或旋转场区。
- 入口、出口、边界与方向箭头始终可见；边界按 45 逻辑像素平滑混合，离开后仅恢复固定向下重力，保留正常速度，不瞬移、不清速。
- 0.3 仅 3-2 及其倒映关各有一个井；不允许场区重叠，不覆盖杠杆/滑轮负载及堆叠目标。全局重力始终不变，不能通过启用局部设施重新开放全局输入。
- 关卡先要求用导流面进入井，再在出口接到高台；入口缺少导流时落入安全回收区、需要调整重试，出口失去承接时不能抵达收集器。井负责提升，玩家仍负责进入与离开路线。

这保留了一关的空间变化，也让“由哪里获得高度”有明确答案。具体几何与参数须以新规则试玩验证，本文不宣称当前关卡布局已经符合要求。

| 1-5 `ch1_l05` | 配重托举→导板落至弹簧→出口承接 | 三段路径连续；任一关键承接缺失均无法入仓 |
| 2-1 `ch2_l01` | 两块限长木板衔接宽缺口，起始坡提供横向速度 | 缺口宽于裸球在允许初速下的飞越距离；少一块不能连通 |
| 2-2 `ch2_l02` | 木板库存设为 0，用有限画线长度画缓坡和护栏越过危险区 | 高位出生提供势能；无画线必落入危险区，多种画法可行 |
| 2-3 `ch2_l03` | 带侧壁的窄通道，缩球后接到下坡出口 | 排除上方绕行；原尺寸过不去，合法缩小能通过 |
| 2-4 `ch2_l04` | 把配重置于一端托盘，另一端承球；用出口板接高台 | 等距反向抬升；固定重力下失去配重不能提升球 |
| 2-5 `ch2_l05` | 在目标区搭三块任务方块，可画有限支撑面；释放观察 3 秒稳定 | 准备阶段不算完成；不稳定摆法释放后坍塌，稳定摆法计时通关 |
| 3-1 `ch3_l01` | 坡道球穿激光开 4 秒门，配置路线使其及时通过；配重保持开关为另一解 | 门封闭旁路；验证时序路线与保持开关各自可解，不强制两者都用 |
| 3-2 `ch3_l02` | 画入口导坡进入升流井，再用出口板接到高台 | 井只负责抬升；去掉入口或出口承接各自导致路径中断 |
| 3-3 `ch3_l03` | 初始坡进入水流，用导板在分岔处选择出水口 | 水流为已知动力；没有导板会走向非目标出口 |
| 3-4 `ch3_l04` | 由高到低经过红→黄→蓝通道，以画线选择正确支路；误染支路通向洗色回收口 | 颜色选择来自路线；误染可回收重试，已得碎片永久保留，不依赖反重力爬回 |
| 3-5 `ch3_l05` | 分层坡道 A→B→C，以有限板/线接通，再经水流与门入仓 | 颜色与顺序约束路线；错序可回到准备调整，拒绝成为无反馈死局 |

首轮迁移的碎片已放到固定重力下经回放验证可达的位置，多数位于主路径。侧支路收集难度留待多人试玩调优；不沿用原悬空坐标。

倒映章首先只做水平镜像：坐标、角度、局部场与水流的水平分量、建造区和摆放区一起变换，全局 `(0,1)` 保持。暂不缩减板/线或削弱弹簧；每个镜像关都须有独立合法解轨迹后开放。后续增加资源挑战必须重新验证可解性。

## 6. 需求编号与数据迁移

旧 FR-14（传感器采集）、FR-16（重力灵敏度）、FR-17（摇杆降级）、NFR-04（姿态控制延迟）退役并保留编号；FR-15 改为固定重力；新增 FR-44（准备/释放/重试）。FR-09、FR-18、FR-24~28、FR-31、FR-36/38、FR-41~43 联动修改。旧编号的测试不得改个标题就宣称覆盖新需求。

| 项目 | 0.3 数据契约（已实现） |
| --- | --- |
| 关卡版本 | 新增 `rulesVersion: 3`；现有无此字段的数据按 0.2 看待，禁止静默当作新关卡 |
| 重力字段 | 以当前源数据字段 `initialGravity` 为准，只接受 `{x:0,y:1}`；旧设计中的 `gravity` 不作为第二份配置 |
| 建造区 | 新增 `buildAreas: [{x,y,w,h}]`，中心坐标矩形；有板/线时必须非空；整件碰撞轮廓须在允许区并集内 |
| 可摆放方块 | 沿用 `draggable` 白名单，新增 `placementZones: {bodyId: [{x,y,w,h}]}`；同时校验区域、支撑与非重叠；禁止包含球和机关主体 |
| 工具 | 沿用 `boards`、`lines`、`resizable`、`scaleRange`；限额与实际尺寸一起进行解轨迹验证 |
| 局部力场 | 沿用 `sensors[].type='gravityField'` 和 `force`；0.3 只允许既定升流井，作用对象限定能量球 |
| 计分与存档 | 新增 `rulesVersion:3` 的成绩与教程标记命名空间；保留旧解锁、碎片和旧成绩供查看，0.3 星级/最优时间重新记录，首次升级提示体验新教学；旧灵敏度和操控方式忽略且不再写回 |

`rulesVersion` 是玩法版本，与已有存档 `version:2` 的存储格式版本分开。已按恢复策略迁移并备份，重玩旧存档不会把旧版成绩冒充新规则成绩。SRS/GDD 中其他未涉及的数据字段仍受 0.2 实施说明约束。

## 7. 实施顺序与完成标准（验证结果见07）

1. **输入与阶段**：`game.js` 移除所有重力写入入口；`pages/index/index.vue` 停止传感器采样/转发；`static/game/index.html` 与样式更新释放、准备和工具禁用状态。`core.js`/`runtime.js` 实现规则版本、阶段、复位、固定重力和升流井边界，`physics.js` 保留引擎内部设置重力能力。
2. **建造与存档**：实现轮廓相交/建造区/摆放区校验、无冲量缩放、配置撤销和玩法成绩隔离，随后迁移三个教学关及 1-2、2-1、2-2。先验证代表关，避免一次性把全部关卡改成无解。
3. **全部关卡**：按 §5 重配剩余布局、碎片和水平镜像，生成 `levels.js`；更新 HUD、提示、README 操作及教程。所有运输关必须有势能或明确动力来源。
4. **验收**：用真实工具操作轨迹替换自由重力控制器；保留物理、Link、染洗、堆叠和存档的有效回归，新增下列检查。全部通过后才把 README 标为 0.3 已实现。

| 检查 | 通过条件 |
| --- | --- |
| 固定重力与输入 | 在准备、运行、暂停恢复、重试、倒映中注入倾斜/滑动/键盘旧输入，全局始终为 `(0,1)`；无姿态权限/无传感器也可完成全部关卡 |
| 阶段隔离 | 准备停留 10 秒，物体/任务/稳定窗不推进；运行中板/线/缩放/拖动/撤销全部无效；反复释放/重试不能累积位置、动量或 Link 状态 |
| 工具合法性 | 穿球画线、重叠扩张、跨建造区木板、区外配重均拒绝且不扣库存；合法曲线与贴边搭建正常；取消触摸不残留半成品 |
| 33 关正例 | 18 普通关 + 15 水平镜像逐关运行，记录准备操作、释放和必要重试；只走公开操作接口，不直接设置球位置/速度、重力或胜利状态 |
| 代表关反例 | 教学2/1-2 去配重，2-1 去桥，2-2 去画线，3-2 去入口/出口承接，各自运行至二星时间上限不入仓；保留其他合法配置用于对照 |
| 替代解探索 | 人工尝试空白释放、贴墙、缩放极值、出口冲量绕行、跨机关架长线、配重砸球；发现跳过主题的稳定通解时重排空间/资源，不追加无理由的打卡条件 |
| 进度与反馈 | 碎片支路可达；误染和错序可重试恢复；旧进度不丢失且新旧成绩分开；阶段、失败原因与局部力场范围可见 |

有限的反例测试不能证明不存在任何旁路。验收同时需要正例操作回放和人工试玩，记录发现的多解；有物理依据且仍利用关卡资源的替代解可保留。
