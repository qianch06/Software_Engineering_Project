## 规则与交互

- 所有中性停泊台永久存在。点击相邻实体平台，再启动输送台；道路交叉不代表连接。
- 换相、转桥、灯键与配重操作只在停泊时可用，先预览再确认。变化的通路用浅金色标出，文字给出开放条件。
- 红相平台为斜纹，蓝相平台为点纹；球保持微光颜色。地图与条件清单始终可以检查。
- K 的钥纹一旦获得持续保存。配重牵引中不压台；放下后留在原节点，换相不使其消失。禁货道路在出发时阻止携带配重进入。
- 每段出发时检查条件，并锁定该段。运行中禁止操作机关、撤销或重置，允许暂停或退出；中断运输会回到上一个完整停泊状态。
- 每次到站或机关操作都保存完整历史，撤销还原节点、相位、桥位、钥纹、配重和灯态。重置仅清除当前关的会话。
- 每关提供三级提示。第四章不计时、不按撤销扣分、不设必拿碎片；选关记录只显示完成状态，旧章节仍使用原评分。
- 使用 `ch4_g01` 至 `ch4_g05`，避免旧第四章记录自动完成新版。完成第三章最后一关后顺序解锁，管理员开关仍可解锁全部关卡。总计 21 关、13 枚原有碎片。

## 实现边界

第四章是固定通路规划玩法，不使用前三章的木板/画线建造。文稿地图只用于确定拓扑与机关条件，不直接作为游玩画面。五关在 scripts/courtyard-scenes.cjs 中重新布置为侧视工坊：实体承重平台、带护栏的滚筒输送带、导轨升降台、可折起的桥板、货物拦截器、配重压板、钥纹与三灯锁。画面复用前三章 Renderer 的材质、绘图工具和玻璃小球，用 Canvas 2D 绘制。

每次释放使用实际场景坐标创建 Matter.js 世界，包含球、载货刚体、托盘、护栏、沿当前路线的输送床/导轨和停泊台碰撞体。上升由机械导轨驱动，重力向下；画面直接绘制球、配重和托盘的物理位置，不将统一小场景投影到抽象连线。输送床在转角留出升降口，到站由实际位置、速度及连续稳定帧判定。

这是分段机械运输，不是自由滚球操作。不同输送路线使用隔离的机械通道，导轨相交处不能中途换乘；球只能在指定实体接驳台选择下一段。每段出发检查并锁定机关状态。全景可检查设备位置，放大场景后可横向、纵向滚动观察；右侧目的地按钮也可选择平台。

保留既有音效与 BGM 配置。页面可离线打开。手机横屏将地图与操作栏并排排列，操作栏可独立滚动查看，节点触控目标至少 48 CSS 像素。
