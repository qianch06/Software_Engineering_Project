## 1. 项目背景信息（本节为上下文资料，非需求项）

> 说明：本节内容用于解释需求的"为什么"，不构成可验收需求；若有疑问以第 4、5 章为准。

### 1.1 创意来源与价值主张
原始创意描述（来源 R0，历史输入；其中倾斜重力已由 0.3 设计修订取代）：
> 制作一款手机横屏 2D 物理解谜游戏，把"空间+物理"做成解谜机制。解谜感来自机关组合：倾斜重力（陀螺仪控制重力方向）、可旋转机关（杠杆/铰链门/滑轮/弹簧板）、触屏手势（双指缩放、拖板搭桥、画线成刚体）、传感器区（激光/水流/重力场触发开关）。目标是把"能量球"送进收集器、让机关按顺序联动、把所有方块叠稳不倒。参考《The Room》的机关感、《人类一败涂地》的软物理缩小版，采用《双相》/《GRIS》的简约风格。

### 1.2 定位与竞品参考
| 参考 | 借鉴点 | 本项目差异 |
|---|---|---|
| 《The Room》 | 机关层次感、逐步解锁的"可触感"操作反馈 | 本项目机关交互全部基于物理（重力学+刚体），而非固定动画 |
| 《人类一败涂地》 | 软物理解谜的"失败也很有趣"氛围 | 缩小到刚体+约束层面，不做角色动画 |
| 《双相》《GRIS》 | 极简扁平配色、低信息噪音、情绪化关卡节奏 | 本作为规则清晰的空间解谜，色彩用于目标提示 |

### 1.3 技术环境与可行性依据（前置调研结论）
- 宿主平台：uni-app（Vue3）编译为 Android/iOS 原生 App，游戏运行于 App 内置 WebView，逻辑为 JS 运行时。
- 物理引擎：Matter.js（当前稳定版 0.20.0，MIT 协议，纯 JS 无原生依赖），可在 WebView 内以固定步长时间循环运行；支持刚体、复合体、约束、碰撞事件、睡眠（sleeping）、重力矢量（engine.gravity）。
  - 机关需求的可行性：杠杆/铰链门/弹簧板对应 Matter.js 的 Constraint（stiffness/damping/angularStiffness）+ Body 组合；**滑轮需自行用"双约束+锚点"或自定义约束模拟（引擎无原生 pulley 原语）**——记入假设 A6 与设计文档决策 D3。
- 输入：0.3 主线仅依赖触控；不启动加速度计，不将设备姿态映射为物理重力。重力是固定世界规则，局部升流井按 FR-31 单独施加区域加速度。旧传感器调研不再作为 FR 或兼容性门槛。
- 渲染：`<canvas type="2d">` 节点画布（uni-app Canvas 2D 节点 API），按 60Hz 与物理同步渲染。
- 横屏：manifest 配置 `app-plus.orientation: landscape-primary` + `plus.screen.lockOrientation` 运行时双保险。
- 持久化：uni 本地缓存（同步/异步 API），单机场景够用。
- 结论：核心玩法在现有技术栈下可实现，性能是否达标（NFR-01）需按 §11 的基准测试验证。

## 2. 产品总体描述

### 2.1 产品愿景
一款以**配置机关、建造路径、释放观察**为核心的极简物理解谜游戏：世界重力固定向下，玩家在准备阶段摆放指定配重、搭桥、画导流面并缩放标记物体，释放后利用落差、杠杆和机关联动把能量球送进收集器。关卡的"机关感"强调连续的正反馈（每次成功触发都有明确表现与下一个目标出现）。

### 2.2 目标用户
| 角色 | 画像 | 关键诉求 | 使用场景 |
|---|---|---|---|
| 玩家-休闲解谜者 | 18–40 岁，喜欢《The Room》《Gris》等"气氛型解谜" | 手感顺滑、失败友好、反馈明确 | 碎片时间，单手持机（躺/坐/通勤），横屏双持 |
| 玩家-硬核挑战者 | 追求三星/全成就 | 可重玩、有星级与重置次数统计 | 反复通关打星 |
| 关卡设计师/开发者 | 团队内部 | 能用 JSON 快速搭关并回归测试 | HBuilderX 开发时 |
| 测试/评审人员 | 团队内部 | 可复现、可观测（调试面板） | 真机兼容测试 |

> 玩家用户不面向：需要账号、联机协作、UGC 社区的功能需求（见 §7 边界）。

### 2.3 核心玩法闭环（玩法循环）
```
┌────────────────────────────────────────────────────────────┐
│  单关循环：读目标 → 观察机关/路径 → 尝试解谜                  │
│    ├─ 准备方案：在限定区域摆配重、搭桥、画线、缩放              │
│    ├─ 释放观察：固定向下重力，杠杆/门/滑轮/弹簧改变路径          │
│    ├─ 返回准备：复位球和机关，保留方案并调整，不积累动量          │
│    ├─ 固定设施：激光/水流/升流井提供可见的区域规则与联动         │
│    └─ 结果：球入收集器（通关）或 球湮灭（重试）               │
│  章节循环：通关解锁下一关 → 三星评价 → 返回选关界面           │
└────────────────────────────────────────────────────────────┘
```

教学关允许聚焦一种操作，正式关围绕一个主机制与一种目标（运输/顺序联动/稳定堆叠）构建路径，组合关再叠加机制。不能用机制数量代替机制必要性；代表关必须执行移除主机制的反例检查（重构方案 §7）。公式：`关卡 = 机制集 ∪ 目标 ∪ 环境约束`。

### 2.4 关卡目标类型（对应"目标"的三类玩法）
- **T1 运输**：把能量球送进收集器（基础目标，贯穿所有关卡）。
- **T2 顺序联动**：按设计顺序依次触发机关链（如 A→B→C）解锁收集器区域。
- **T3 稳定堆叠**：把全部方块叠放并保持稳定 N 秒不倒（时间相关功能 `[T]`）。

### 2.5 影响力范围与包络
- 交付内容：可安装 APK/IPA、15 个正式关卡（3 章 × 5 关）+ 3 个教学关（§4 B 组 FR-09）、碎片收集与《倒映章》复玩内容（§4 K 组 FR-42/43）、开发者关卡编辑器（内置于调试面板，面向开发/测试）。
- 不含：付费、广告、账号、云服务、多人在线（§7）。

## 3. 需求定义总则

### 3.1 编号规则
- 功能需求：`FR-XX`（按模块分组编号，见下）；非功能需求：`NFR-XX`。
- 后置需求（后续版本）：`FR-XX(后)` / `NFR-XX(后)` 标注于优先级表，不进入本期基线。
- 设计文档中引用格式：`FR-15` → `SEC-4.2`（需求→设计元素）。

### 3.2 优先级（MoSCoW）定义
| 级别 | 含义 | 与使用频率的关系 | 遗漏后果 |
|---|---|---|---|
| **H（Must）** | 必须实现，否则产品不可用 | 每关/每次会话都会用到 | 崩溃级的缺失 |
| **M（Should）** | 应有，可给过渡替代方案 | 会话内周期性出现或特定类型关卡使用 | 明显体验损失，可降级 |
| **L（Could）** | 可选 | 低频或增强体验 | 不影响核心闭环 |

### 3.3 验收标准（AC）文法约定
每条验收格式：**“当 [前提] 时，执行 [操作/输入]，则 [可观察结果]，误差/阈值 [指标]。”** 必须可由测试用例或真机操作直接判定，禁止出现"良好、流畅"等不可测量措辞。

- §1 仅作背景；凡需求必须出现在 §4（功能）、§5（非功能）、§6（约束）、§9（数据格式）中，且以 `FR-` / `NFR-` / `C-` / `IO-` 编号。

## 4. 功能需求（FR）

> 每条含：说明（优先级）、输入/前提、输出/结果、验收标准（可测试）、来源。来源代号见 §12.1。`[T]` 表示时间相关功能。

### A 组 · 平台与生命周期

| 编号 | 名称 | 优先级 |
|---|---|---|
| FR-01 | 横屏锁定 | H |
| FR-02 | 前后台生命周期自动暂停 | H |
| FR-03 | 异常退出后的进度恢复 | M |

**FR-01 横屏锁定**
- 说明：游戏仅以横屏运行；启动即锁定横屏（左右均可，`landscape-primary` 优先），运行中不可旋转为竖屏。
- 输入/前提：冷启动或从后台恢复。
- 输出/结果：应用进入横屏，且运行中不随设备旋转而改变方向。
- 验收：在 Android ≥8 / iOS ≥13 真机上，无论设备静止横置何方向，App 启动 2s 内保持横屏；运行中旋转设备 UI 不发生旋转/错位。
- 来源：R0（手机横屏游戏）；C-1（技术方式见设计文档）。

**FR-02 前后台生命周期自动暂停（自动暂停）`[T]`**
- 说明：App 退后台或来电时，立即暂停游戏（物理、音频、计时），返回前台时保持暂停态并显示"已暂停"遮罩，由玩家手动"继续"。
- 输入/前提：`onHide` / `onShow` 生命周期事件。
- 输出/结果：后台期间物理不推进、不倒计时；回前台处于暂停，无进度损失。
- 验收：进入关卡后切后台 10s 再返回：物理世界停止、计时未增加、显示暂停界面；点"继续"后从暂停态恢复。
- 来源：用户场景（碎片时间）；行业规范（移动游戏防作弊/防耗电）。

**FR-03 异常退出后的进度恢复**
- 说明：App 被系统杀掉/崩溃后重启，自动恢复到最近一场"进行中关卡"的关卡开头（不恢复瞬间物理现场），或恢复到主菜单并明确提示。
- 输入/前提：异常退出前的最近一次已进入关卡及其最小现场快照（启动时自动保存）。
- 输出/结果：重启后 1 次点击内回到该关开头（已清空玩家手势产出，机关复位）。
- 验收：在关卡中崩溃（测试注入）→ 重启 → 进入该关卡开头且关卡结构完整、存档设置不丢失。
- 来源：NFR-06 可靠性推导；评审补项。

**FR-04 主菜单与"继续"**
- 说明：启动进入主菜单，含：开始游戏、继续（存在未完成关卡时）、设置、关于。
- 输入/前提：App 启动完成；逻辑坐标基准见 FR-05 的坐标说明（不在此重复）。
- 输出/结果：点击各按钮进入对应页面；"继续"直接进入最近未完成关卡。
- 验收：全部按钮点击有明确跳转；首次启动无"继续"入口，有存档后出现。
- 来源：R0；通用游戏流程。

**FR-05 章节/关卡选择界面**
- 说明：以章节为组展示关卡（3 章 × 5 关 + 教学关），已解锁关卡可选、未解锁显示锁并提示解锁条件；关卡格显示星级。
- 输入/前提：主菜单"开始/继续"。
- 输出/结果：选中关卡后进入该关卡；点击锁定关卡不进入并给出提示文案。
- 验收：解锁规则正确（通关第 N 关解锁第 N+1 关）；星级显示与存档一致。
- 来源：R0 关卡节奏；FR-40。

**FR-06 关卡内 HUD**（横屏：顶部与底部条带）
- 说明：关卡内常驻 UI 含：返回/暂停按钮、重置本关按钮、目标提示入口（可开关）、当前目标进度（如"1/2 球入仓"）、关卡名；底部为手势工具栏（木板库存、画线开关、撤销）与“释放/返回准备”按钮；明确显示当前阶段，运行中建造入口禁用。
- 输入/前提：进入关卡。
- 输出/结果：各控件点击生效；不遮挡玩法区核心区域（玩法区占屏中央 ≥ 70% 高度）。
- 验收：在 19.5:9 与 16:9 两款真机上，HUD 可点区域不与被球/机关碰撞区域重叠；控件响应即点即生效。
- 来源：R0；可用性设计推导。

**FR-07 暂停菜单**
- 说明：暂停菜单含：继续、重新开始本关、返回关卡选择、设置、退出到主菜单。
- 输入/前提：点 HUD 暂停按钮或 FR-02 触发的自动暂停。
- 输出/结果：暂停时物理完全冻结（渲染保留最后一帧）；各菜单项按语义生效。
- 验收：暂停期间帧循环停止（通过调试面板确认 dt=0）；"重新开始"把本关恢复到初始状态（含球与手势产出）。
- 来源：通用游戏流程；FR-02。

**FR-08 设置界面**
- 说明：设置项：触控灵敏度、音效开/关、振动开/关（对应 NFR-14 触觉反馈）、重置所有进度（二次确认）。
- 输入/前提：主菜单或暂停菜单进入设置。
- 输出/结果：设置即时生效并持久化（FR-40）。
- 验收：修改任意设置→重启 App→设置保持；"重置进度"需二次确认，确认后清除进度数据。
- 来源：NFR 体验推导；FR-37、FR-41 依赖。

**FR-09 新手教程（教学关卡序列）**
- 说明：教学1 教固定重力下放斜板与释放；教学2 只教拖放配重驱动跷跷板（出口桥预先搭好）；教学3 只教画线承接，缩放延后到第二章。采用步骤面板与区域高亮，允许试错。
- 输入/前提：首次进入该教学关。
- 输出/结果：展示“准备→释放→观察→返回准备调整”的完整循环；步骤随实际操作推进。
- 验收：三个教学关分别完成搭桥、配重、画线与释放；每步停留 30s 内给出明确提示；无传感器环境同样可完成；单独不放主题工具的初态不能自动入仓。
- 来源：R0（机关与建造）、R4（移除万能重力操控）。

**FR-10 通关结算界面**
- 说明：通关后显示结算：星级（1–3，依据 FR-38 评价规则）、通关用时、重置次数；按钮：下一关、重玩、返回选关。
- 输入/前提：FR-39 判定通关成功。
- 输出/结果：结算正确分档；写存档（FR-40）；"下一关"按解锁序跳转。
- 验收：三次不同表现（快而干净/有重置/耗时）各得到符合规则的星级，存档同步。
- 来源：R0 目标玩法；FR-38。
### C 组 · 物理引擎与基础实体

| 编号 | 名称 | 优先级 |
|---|---|---|
| FR-11 | 物理引擎封装（PhysicsService） | H |

**FR-11 物理引擎封装（PhysicsService）**
- 说明：基于 Matter.js（0.20.x）封装统一物理服务层，业务代码不得直接依赖 Matter.js 类型；提供：世界创建/销毁、固定步长推进、刚体增删改、约束增删、重力矢量设置、碰撞与查询接口。

**FR-12 基础实体**

**FR-13 碰撞事件回调**

- 输入/前提：碰撞发生时。
- 输出/结果：事件在下一物理步进后、渲染前派发；同一对实体在同一连续接触期间"开始/结束"各触发一次。

- 来源：FR-18~23、FR-29~34 全部依赖；SS-04。

**FR-18 杠杆（lever）**
- 说明：绕支点旋转的跷跷板/压杆；质量、力臂与限位共同决定运动。玩家仅在准备阶段于指定承托位摆放配重，不能拖动球或杠杆。杠杆用于托举、改变坡向或开门。
- 输入/前提：释放后球或配重压在板面，产生不平衡力矩。
- 输出/结果：较大力矩一侧下沉，另一侧抬升；到位可触发 Link，持续接触不重复触发进入事件。
- 验收：固定向下重力、相同初态下，增加一侧配重或力臂可使该侧下沉；等质量不等臂时长臂侧下沉；限位不越界。1-2 无配重时不能到达高台，有合法配重与路径时可达，不额外设置“碰过杠杆”入仓条件。
- 来源：R0（杠杆）；R4（恢复力矩与高度差的解题作用）。

**FR-19 铰链门（hinge door）`[T]`**
- 说明：绕单点铰链旋转的门体：可被碰撞推开/弹回，或由开关控制开合（配置 openAngle/closeAngle/回弹弹簧刚度）；关门可形成"通过后需要特定时机"的时序玩法。
- 输入/前提：碰撞或 Link 触发（FR-22）。
- 输出/结果：门按配置旋转到目标角度；可配置半开（延时关闭 `[T]`）行为。
- 验收：用球撞击开门：门旋转到 openAngle（误差 ±3°）并在配置延时后闭合；开关式门在触发后 500ms 内开始动作。
- 来源：R0（铰链门）；R0（路径时序）。

**FR-20 滑轮（pulley）**
- 说明：绳索跨滑轮连接两个负载：两端质量差驱动重端下降/轻端上升；绳索长度/两端锚点可配置。**实现方式：Matter.js 无原生 pulley，以"双长度约束 + 定滑轮锚点"或自定义约束模拟（见假设 A6 / 设计决策 D3）**。
- 输入/前提：一端挂载能量球/方块（质量变化）。
- 输出/结果：质量大端下降，另端上升；到位后触发 Link 或稳定。
- 验收：在测试关令左端质量=2×右端：两端等距反向运动、总绳长保持，质量差影响加速度；不产生 2:1 速度倍率（同 0.2 修正）。
- 来源：R0（滑轮）。

**FR-21 弹簧板（spring board）**
- 说明：一端固定于平台、另一端可做短行程线性/旋转弹跳的板件：物体压入压缩弹簧，离板时获得向上弹射速度；可配置 stiffness/damping/弹射增益/触发阈值。
- 输入/前提：能量球/方块以碰撞速度压入。
- 输出/结果：球被弹射，离开速度方向近似垂直板面；弹跳高度按配置增益（相对自由落体回弹比）。
- 验收：固定高度释放球，弹射后峰值高度 ∈ [配置预期 ±15%]；连续弹 20 次无飞越配置能量上限导致的 NaN 或失控。
- 来源：R0（弹簧板）。

**FR-22 机关"触发源 → 目标"开关语义（Link）**
- 说明：统一链接机制：任一"源实体"（机关到位/传感器激活/球到达或其颜色状态）发出事件，绑定到"目标实体"（门开合/桥升降/力场开关/收集器解锁）执行动作；语义可配：`once`（一次性）、`hold`（保持：源释放则目标回位）、`toggle`（翻转）、`pulse`（脉冲 N ms）。**触发时必须有可见因果提示**（源→目标的 Link 流光/连杆动画，机关感要素①：视觉因果可见）。
- 输入/前提：源事件满足触发条件。
- 输出/结果：目标按配置语义执行且结果可逆（hold/toggle 可复原，once 不可复原）；Link 流光与目标动作同步出现。
- 验收：对四种语义各建测试场景：同一输入序列下目标行为与配置一致；hold 语义在源释放后目标回位时间 ≤300ms；once 语义只能生效一次；**任意 Link 触发时源→目标因果提示可见（时长 ≥600ms，出现延迟 ≤1 帧）**。
- 来源：R0（传感器区触发开关、按顺序联动的基础抽象）；SS-03 派生；评审（三要素①）。

**FR-23 顺序联动机关链 `[T]`**
- 说明：关卡可声明"机关链条"：必须按指定顺序依次触发（如 A→B→C），任意乱序或错序不推进，且给出可感知的错序反馈（目标 UI 闪烁/机关弹回）；全部按序完成后触发最终事件（解锁收集器/通关）。
- 输入/前提：链上各源按序产生对应事件。
- 输出/结果：链状态推进并可视化（HUD 显示进度 A✓ B→ C）；错序时不满足最终条件且给反馈，并在链进度区留下"最近错触发痕迹"（如 `A(✕)`，直至下一次合法触发才清除）——机关感要素③（可逆+不羞辱+错过留痕）。
- 验收：正序 A-B-C 依次触发→最终事件发生（如收集器解锁）；乱序 C-A-B→最终事件不发生、出现错序反馈 ≤1s、且链进度区显示 `A(✕)` 痕迹（下一次合法触发后清除）；链状态在重开/重置后复原。
- 来源：R0（让机关按顺序联动）。

**FR-24 双指缩放改变物体大小**
- 说明：目标物体（关卡标记 `resizable`）进入"缩放模式"（关卡开启或用户框选后），双指捏合缩放其尺寸；缩放受 [minScale, maxScale] 限制（关卡配置，典型 0.4–2.0）；仅准备阶段可缩放，尺寸作为释放初态；运行中禁止缩放，扩张与其他刚体重叠则拒绝，避免注入冲量。**质量语义统一为密度守恒**（缩小变轻、放大变重，质量 ∝ 面积，依赖 Matter `Body.scale`，见设计决策 D4）；由此产生两条关卡设计红线：
  1. 水流域/强推力区与缩小球不得形成"轻球被冲走"的反直觉组合（同关设计规避）；
  2. 与弹簧板同关时，可缩放范围强制收窄至 [0.7, 1.3]（Schema 联动约束，见设计文档 SEC-5.2 InteractiveSpec）。
- 输入/前提：准备阶段，双指在标记物体触控区内捏合；新轮廓合法且不与其他实体重叠。
- 输出/结果：物体尺寸连续变化到手势比例（比例映射：缩放因子 = 手势伸长/起始跨度，±5% 误差），到达边界后停止并给边界反馈（轻微回弹动画/振动）；质量按密度守恒自动更新。
- 验收：在缝隙关卡中，球 1.0→0.5 缩放后能穿过 0.6 宽窄缝（0.5 直径 < 缝宽）；缩放比例连续无跳变（采样 ≥30Hz 手势数据）；缩放到 maxScale 后无法继续；**缩放后质量与面积成比例（密度不变，误差 ≤3%）**；红线①/② 的组合关卡数据在 Schema 校验层被拒绝，无法加载。
- 来源：R0（双指缩放改变物体大小（穿过缝隙））；评审（密度守恒语义拍板）。

- 输入/前提：能量球与激光感测区发生几何相交。
- 输出/结果：几何相交瞬间产生 trigger 事件；渲染同步点亮/变色；绑定目标按 FR-32 语义执行；若配置 `dye`，同时发 `ball.dyed` 变色事件（FR-33）。
- 验收：球缓慢滚过激光区：恰好触发 1 次 trigger、1 次 release（若配置可复位）；渲染颜色变化与事件同步（≤1 帧）；**配置 dye 的激光使球染色后离区保持，进入洗色区后 1s 内恢复 white；误染路径须通向可见洗色回收口或允许返回准备重试，不要求球逆着固定重力返回上游；恢复可达性以解轨迹验证，不能仅凭 Schema 声称成立**。
- 来源：R0（传感器区：激光 … 触发开关）；评审（四色染洗机制拍板）。

**FR-30 水流影响区**
- 说明：水区域（矩形/多边形）对其中物体施加持续推力场（方向+强度），模拟水流推动能量球进入管道/机关；球入/出区域时推力平滑渐变（防跳变）。
- 输入/前提：物体（能量球为主）质心进入区域。
- 输出/结果：区域内物体沿水流方向获得加速度（强度可配）；离开后消退。
- 验收：水平水流区 中速球进入后 1s 内偏转方向与水流方向夹角 ≤10°；球离区后 500ms 内水流影响为 0。
- 来源：R0（水流 … 触发开关）；派生 T1。

**FR-31 固定升流井（沿用局部重力场数据类型）**
- 说明：0.3 仅第三章 3-2 及其水平镜像配置固定升流井。只影响能量球，区内合加速度替换为作者配置的向上向量，大小不超过基准重力的 2 倍；位置/范围/方向不可由玩家调整，不与其他场重叠，不作用于机关、配重和堆叠方块。
- 输入/前提：运行阶段球进入可见区域，边界 45px 内平滑混合。
- 输出/结果：球在井内提升，离区后恢复固定向下加速度且保留速度；全局重力始终 `(0,1)`。玩家须搭建入口导流和出口承接。
- 验收：区内测得配置合加速度（误差 ≤10%），区外恢复向下，其他刚体不受局部场影响；去掉入口或出口承接分别不能入仓；出口动量不能绕过主题路线。
- 来源：R0（空间变化）；R4；重构方案 §4。

**FR-32 传感器触发开关语义**
- 说明：传感器区的触发统一走 FR-22 的 Link 语义（`once/hold/toggle/pulse`）；无目标绑定的传感器可仅为"读数/成就"用途（计分）。
- 输入/前提：FR-29/30/31 任一产生事件。
- 输出/结果：按 Link 语义驱动目标；同帧多传感器并发时按绑定优先级串行执行（可配置顺序）。
- 验收：激光区→保持打开的门：球离区后门在 ≤300ms 回到关位；两个传感器同时出发（绑定同一目标）不产生重复状态翻转。
- 来源：R0；FR-22 复用。

### H 组 · 能量球与收集判定

| 编号 | 名称 | 优先级 |
|---|---|---|
| FR-33 | 能量球实体与多球支持 | H |
| FR-34 | 收集器（目标仓） | H |
| FR-35 | 死亡区/湮灭区 | H |
| FR-36 | 失败与关卡重试 | H |

**FR-33 能量球实体与多球支持**
- 说明：能量球为主解谜载体：圆体动态刚体、受 FR-15 重力/机关/场影响；携带视觉辉光；携带 `color` 状态（white/red/yellow/blue，仅经染色激光或洗色区改变，FR-29），染色事件 `ball.dyed` 广播到渲染与任务层；关卡可含多个球（如同步入两仓）。
- 输入/前提：关卡配置球的出生点/数量。
- 输出/结果：球按配置生成并受全套物理规则约束；被相机限定在玩法区边界内（越界视为 FR-35）。
- 验收：加载双球关卡：两球独立受物理与重力作用，互不穿行、颜色状态互不干扰；球被弹簧板弹起后运动符合参数；**球颜色变化时 `ball.dyed` 事件 ≤1 帧送达渲染层**。
- 来源：R0（目标主体）；评审（四色染洗机制拍板）。

**FR-34 收集器（目标仓，含颜色过滤）**
- 说明：收集器为"目标交互体"：通常是碗状/圆形的传感腔体；能量球进入腔体（质心+半径判定）触发"收纳"事件：球被吸附动画收容、计数 +1、播放反馈。可配置 `acceptColor`（仅收纳该色球，《三色回廊》机制）：**非匹配色进入不收纳、不销毁**，给予小力度弹回 + 拒绝音/振动反馈（与彩色门同一语义，见 FR-22 扩展/设计决策 D13）。
- 输入/前提：球进入收集器感测范围。
- 输出/结果：收纳事件写任务计数（FR-37）；已收球不可再出（可配置"收容扣留"）；非匹配色球被拒绝但保留在场。
- 验收：球滚入收集器：计数 +1 且球不再回到玩法区（5s 后仍在仓内）；计数达到关卡要求后 2s 内触发 FR-37 通关；**匹配色入仓计数+1；非匹配色入仓不计数、不销毁、≤300ms 内给出拒绝反馈**。
- 来源：R0（把能量球送进收集器）；评审（四色染洗机制拍板）。

**FR-35 死亡区/湮灭区**
- 说明：关卡可配置湮灭区域（深渊/岩浆/齿轮区）：球进入立即销毁并进入失败/重置流程；方块掉入则仅销毁该方块并播报。
- 输入/前提：任何动态物体进入死亡区。
- 输出/结果：销毁该物体；若被销毁的是任务关键球（FR-33），触发 FR-36 重置或 FR-39 失败。
- 验收：球进入死亡区：300ms 内销毁且触发重置流程；方块进入死亡区：仅销毁方块、球不受影响。
- 来源：R0（失败条件）；R0 过关碎片。

**FR-36 失败与关卡重试**
- 说明：球湮灭或关键任务方块损毁时进入失败态；玩家可返回准备保留方案，或重置本关清空方案。统一执行 FR-44，不单独传送球而保留机关末态。
- 输入/前提：运行失败，或玩家主动返回准备/重置。
- 输出/结果：球回初始出生点，所有机关、颜色、速度、Link（含 once/hold）与顺序链一起复位；永久碎片保留，累计计分与重试次数不清零。
- 验收：失败后一次点击可回准备；连续重试 20 次无动量或 Link 累积；返回准备保留板线，重置则清空并返还库存。
- 来源：R0 体验（失败友好）；R4；FR-28/44。
### I 组 · 关卡目标、判定与编辑

| 编号 | 名称 | 优先级 |
|---|---|---|
| FR-37 | 通关成功判定（目标达成） | H |
| FR-38 | 三星评价与通关用时统计 `[T]` | M |
| FR-39 | 堆叠稳定性判定 `[T]` | M |
| FR-40 | 关卡数据驱动与开发者编辑 | M |

**FR-37 通关成功判定**
- 说明：依据关卡目标类型组合判定通关：T1 运输（收集数量达标）+ 可选条件（机关链完整/时间限制/T3 稳定达成）。判定通过后冻结物理、播放通关演出、进入 FR-10 结算。
- 输入/前提：FR-34 计数 / FR-23 链完成 / FR-39 稳定窗口结束。
- 输出/结果：判定事件生成 → 冻结计时 → 结算界面。
- 验收：构造覆盖 T1/T2/T3 及组合目标共 6 个测试关卡：均能在目标达成时 ≤2s 内触发通关；未达成时（保持球在场）不误判。
- 来源：R0 三类目标。

**FR-38 三星评价 `[T]`**
- 说明：沿用 0.2 的时间与重试评分：三星需在本关第一时间阈值内且零重试；二星需在第二阈值内且最多两次重试；其余通关一星。用时按 FR-44 累计准备与运行的前台活跃时间；成绩按玩法版本记录到存档（FR-41），不增加手势利用率权重。
- 输入/前提：FR-37 通关事件 + 本关统计量。
- 输出/结果：星级与最快成绩写入存档；结算界面正确展示。
- 验收：用脚本化输入制造三种成绩（快/中/慢）：分别获得 3/2/1 星；重复通关取最优（星与时间不降级）。
- 来源：R0 目标用户（硬核挑战者）。

**FR-39 堆叠稳定性判定 `[T]`**
- 说明：T3 目标：全部任务方块静止（角速度与线速度低于阈值持续 N 秒，默认 3s），且无超出平台边界；判定窗口内任一方块速度超阈值则计时清零重计；提供 HUD 倒计时/进度环。
- 输入/前提：关卡目标类型为 T3；方块状态事件。
- 输出/结果：窗口走满 → 通关；不满足 → 不清零继续观察（进度可见）。
- 验收：堆叠测试关：堆 5 块保持 3s → 通关；在第 2s 推倒 → 计时归零且不误判；方块滑出台面 → 该方块状态"失败"，总体判定不通过。
- 来源：R0（把所有方块叠稳不倒）。

**FR-40 关卡数据驱动与开发者编辑**
- 说明：所有关卡由校验过的 JSON 数据描述（§9.2），游戏加载时按数据实例化（不做硬编码关卡）；提供开发者调试面板：加载/重载关卡、查看实体与 Link、单步物理、导出当前关卡快照。
- 输入/前提：LevelData JSON（开发者在 HBuilderX 编辑）；调试面板操作。
- 输出/结果：非法 JSON/字段返回可读错误（§9.2 校验规则）；调试面板可观测运行时状态。
- 验收：用 Schema 校验器对全部标准关卡批量校验 0 错误；手改一个字段为非法值（如 angle=NaN）加载时报错并拒绝进入关卡；调试面板可导出与重载同一关卡结果一致。
- 来源：可维护性（NFR-09/10）；R（关卡设计师角色）。

| A-1 | 目标机型的 CPU 可稳定支撑 Matter.js 220 刚体 + Canvas2D 60fps | 类似体量网页物理解谜在安卓 WebView 上可运行；实测见 §11 基准测试 | 若 NFR-01 不达标 → 降低 NFR-02 上限、启用渲染降级（设计 SEC-7） |

## 7. 边界（明确"不做"，防止蔓延）

以下内容**明确不属于本期需求**，任何需求不得隐式依赖它们：
1. 多人在线/异步协作/排行榜联网（网络能力被 C-4 排除）。
2. 玩家自建关卡与分享（保留 LevelData 驱动为扩张路径，但本期不做 UGC 上传/下载）。
3. 内购、广告、云存档（C-4）。
4. 3D/伪 3D 表现（美术风格限定极简 2D，见 §2 参考）。
5. 手柄/键鼠外设适配（触屏为唯一输入；H5 联调除外）。
6. 玩家全局重力控制、全局翻转、重力摇杆与姿态操控不属于 0.3；局部升流井仅限 FR-31，不做变速/时间冻结。
7. 竖屏模式或 iPad 专用横版布局（仅手机横屏；平板按比例放大运行）。
8. 语音/文字社交功能。
9. 无障碍完整规范（仅 NFR-14 的振动+对比度两项，不承诺 iOS VoiceOver 全量）。
10. 性能工具箱（Profiler 属性页）对玩家隐藏，仅调试面板提供（FR-40）。
11. 颜色混合染色（橙/紫/绿）与"画线挡光"不进入本期（属《三色回廊》后置候选，见附录变更记录）。
12. 软体绳索摆荡等新物理交互不进入本期（手感攻坚题，1.0 后候选）。
13. 时间回退/画线延迟实体化/线染重力等"高阶时序机制"不进入本期（后置候选）。

## 10. 故障模式与处理（FM）

> 每种故障：检测手段 / 处理路径 / 恢复策略 / 对应需求。

| 编号 | 故障模式 | 触发/表现 | 检测手段 | 处理路径 | 恢复策略 | 关联 |
|---|---|---|---|---|---|---|
| FM-01 | 旧重力输入残留 | 升级后旧设置、快捷键或原生事件试图改变重力 | 版本迁移与全局常量断言 | 忽略旧输入，恢复固定 `(0,1)`；不切摇杆 | 触控与释放始终可用，记录开发日志 | FR-15, FR-41, FR-44 |
| FM-02 | 物理发散/NaN/刚体爆炸 | 物体速度/位置为 NaN 或超阈值（如速度 >10⁵） | 每帧检查关键刚体 position/velocity 有限性；速度跑飞看门狗 | 停止该世界步进（冻结界面）→ 弹"物理异常，已重置本关" | 重置本关（FR-07 重置流程）并累计上报调试日志 | FR-11, FR-37, NFR-06 |
| FM-03 | 性能不达标（帧率过低） | 掉帧至 <30fps 持续 2s | 帧时间统计（滚动窗口） | 逐级降级：关闭辉光粒子→降低画线分辨率→缩 camara 渲染内缩→(最后)暂停等待恢复 | 性能恢复后逐级还原；升级策略见设计 SEC-7 | NFR-01/02 |
| FM-04 | 本地存储读写失败/空间不足 | setStorage 抛错/fail | try-catch + fail 回调 | UI 提示"进度保存失败"；关键写档重试 2 次（间隔 1s） | 内存中继续；下次成功写档兜底；记录日志 | FR-41, FR-03 |
| FM-05 | App 前后台切换（进程可能被杀） | onHide 触发 | 生命周期钩子 | 立即暂停+自动落盘（最小现场快照） | 回前台暂停态；被杀则走 FR-03 恢复 | FR-02/03, FR-41 |

| FM-08 | 手势误触/多指冲突 | 缩放误触发/画线误生成 | FR-27 仲裁 + 历史栈 | 撤销（FR-28）兜底；实体生成前有 300ms 半透明"预览确认期"（可配置关闭） | 撤销/清理回滚 | FR-27, FR-28 |

| FM-10 | 机关状态不一致（Link 悬空） | 数据引用失效 | LevelData 校验拒绝；运行时事件目标为 null 报错 | 沙箱化（该 Link 禁用）+ 日志 | 关卡重载校验失败则 FM-07 | FR-22, FR-40 |
| FM-11 | 倒映章迁移无解/不稳定 | 镜像校验、有限性或合法操作回放失败 | 构建与验收检查（FR-43） | 阻止该关发布，返回作者修正；不自动缩工具或改重力 | 正常章保持可玩；重跑正例后开放 | FR-43, NFR-06 |

### 12.2 正确性与可行性论证要点
1. **无对用户无意义的功能**：评审剔除项记录——(a) "摇一摇换色球"（干扰核心循环）；(b) "相机截图分享"（C-4 无网络）；(c) "重力场叠加复数场"（超出谜题理解成本，保留单场叠加但仅 1 层）。凡被剔除者不在 §4 出现。
2. **假设有依据**：A-1~A-7 各自给出依据（§6.2），并标注被证伪后的影响路径。
3. **故障模式有定义**：FM-01~FM-10 均有检测/处理/恢复三要素（§10）。
4. **现有技术可实现且达到性能**：可行性依据 §1.3；Matter.js 约束有技术依据，0.3 不依赖姿态 API；抽样量级（220 刚体）在同类 WebAssembly/JS 引擎场景属保守可用区间；NFR-01 通过基准关卡实测闭环（§11.2）。
5. **时间相关功能已识别**：FR-02、FR-19、FR-23、FR-26（耗时上限）、FR-38、FR-39、FR-44（释放/计分）、FM-09（静滞计时）均标注 `[T]`，其时间语义在验收中量化。
